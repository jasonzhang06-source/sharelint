# ShareLint 1.2.1 — predictable cancellation and pipe failures

Historical development record. This intermediate tag and release are not being
restored. Its changes are included in [2.0.0](v2.0.0.md); use the current
[installation guide](../troubleshooting.md), not this checkpoint, to install.

## Fixed

- Ctrl+C now produces a brief cancellation message and exit `130`, rather
  than an interpreter traceback. Interrupted work is never reported as success.
- Closed output pipes, including buffered `config show`, help, and version
  output, now exit `2` consistently instead of failing during interpreter
  shutdown with exit `120` and an ignored-exception traceback.
- Output flush failures use content-free diagnostics and do not echo native
  exception details.
- Added an interruption regression proving that cancellation during private
  receipt publication rolls back the owned ZIP and report, preserving input.

Normal scan, pack, config, and verify results, schemas, and resource limits
are unchanged. Cancellation can occur after an output has already completed;
review any existing outputs rather than assuming none were created.
