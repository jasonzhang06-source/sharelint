# ShareLint 2.0.0 — plan, pack, and verify locally

This release brings the changes from **1.0.0 directly to 2.0.0**. The intermediate
development milestones are included in this upgrade, not published separately.
The original 2.0.0 source and standalone archives are restored without changing
their contents; this is not a rebuild with newer development changes.

## What's new since 1.0.0

### Reusable policies and explicit configuration

- Use built-in `public` and `strict` profiles or create custom profiles in a
  versioned TOML configuration.
- Create a configuration with `config init` and inspect effective settings with
  `config show`; set finding thresholds and resource limits explicitly.
- Configuration is never auto-discovered inside scanned content. Packing still
  requires complete coverage, regardless of the selected profile.

### Offline receipt verification

- Use `verify` to check the bindings between a delivery ZIP, its private receipt,
  and its private JSON report without uploading or extracting their contents.
- Validate document structure, recompute summaries, and check report/archive
  digests, policy consistency, and the archive's file manifest.
- Optionally pin a receipt digest obtained through a separately trusted channel.
  Integrity verification does not authenticate a publisher or guarantee privacy.

### Report comparisons

- Use `diff` to compare aggregate rule/severity counts and coverage in two native
  JSON scan reports, with console, JSON, or standalone HTML output.
- Changed settings, reduced inspection, and incomplete coverage require review.
  Fewer findings do not prove that a particular secret was removed.

### Reviewable handoff plans

- Create and inspect a private handoff plan before packing.
- `pack --plan` requires the source, effective policy, producer version, and scan
  snapshot to match the plan, and still performs fresh scans and packing checks.
- Bind the exact plan bytes to the receipt and verify the bound handoff offline.

### Reliability fixes

- Handle Ctrl+C with cancellation exit code `130` and without a traceback.
- Handle closed output pipes consistently with exit code `2`.
- Strengthen file identity and read-size checks during packing, and avoid
  regular-file-to-FIFO races hanging supported file reads.
- Correct enum validation behavior on Python 3.11.

## Breaking change: receipt schema 2.0.0

New receipts use zero-based `files[].entry` indices instead of repeating
filenames in `files[].path`. Update receipt consumers to handle the new schema,
or use `sharelint verify`, which accepts both legacy v1 and new v2 receipts.

Native scan reports remain schema `1.0.0`, and SARIF remains `2.1.0`. Existing
scan/pack defaults are retained; handoff plans are optional. Input files and ZIP
member names are not renamed or sanitized by this receipt-format change.

## Download and run

Choose the archive for your machine from **Assets** below, and verify it against
the matching `.sha256` file before running it:

- Linux glibc x86-64
- Windows x86-64
- macOS Apple silicon (ARM64)
- macOS Intel (x86-64)

The standalone archives include Python. After extracting one, run
`sharelint --version` (expected: `2.0.0`) and `sharelint demo`.
On Linux/macOS, use `./sharelint` when running it from the extracted directory.

PyPI publication: **2026-09-21 (Asia/Shanghai)**.

With Python 3.11+ and pipx installed, use the
[PyPI 2.0.0 package](https://pypi.org/project/sharelint/2.0.0/):

```sh
pipx install 'sharelint==2.0.0'
sharelint --version
sharelint demo
```

For an existing pipx installation, use `pipx install --force 'sharelint==2.0.0'`.
The uv equivalents are `uv tool install 'sharelint==2.0.0'` and
`uv tool install --force 'sharelint==2.0.0'`. Choose one installation method.

The PyPI file is `sharelint-2.0.0-1-py3-none-any.whl`: package version `2.0.0`,
wheel build `1`. The original PyPI filenames cannot be reused after deletion.
This new wheel keeps the original runtime code, updates its description and
build records, and does not include a new source distribution. The original

## Try a planned handoff

Use a directory containing files you intend to share, and keep the output paths
outside that directory. Each output path must be new.

```sh
sharelint plan create ./handoff -o handoff.plan.json
sharelint plan inspect handoff.plan.json
sharelint pack ./handoff -o delivery.zip --plan handoff.plan.json
sharelint verify delivery.zip --receipt delivery.zip.sharelint.json --report delivery.zip.sharelint.report.json --plan handoff.plan.json
```

A blocked plan or incomplete inspection cannot authorize packing. Plans,
reports, and receipts remain private working documents.

## Scope and limitations

Inspection stays local, with no third-party runtime Python dependencies. This
release does not add OCR, image-pixel inspection, automatic cleaning, or a GUI.
Plans and unsigned receipts are not signatures or approvals; a passing result
describes the configured checks, not a guarantee of safe sharing.

SHA-256 checks detect byte mismatches, not publisher identity. The Windows
executables are not Authenticode-signed; macOS executables are ad-hoc signed,
without Developer ID signing or notarization.
